# 从职责出发全量重构目录与模块边界

2026-11-12 决定：不做最小整理，改为一次性重定项目文件职责、目录结构、模块边界和路径来源。

原因是三类东西长期混在一起：长期策略与文档、程序运行数据、每次操作的临时证据。只清理 `.local/` 会复发；逐个补丁式改路径会让同一事实散落在代码、文档、技能和测试中。同时，`GLOSSARY.md` 的 Change Set 仍按「单个路由组」定义，而 `route apply --yes` 早已按整份规范逐组应用；`AGENTS.md` 仍写「一次计划只改变一个路由组」。这些不是措辞过时，而是语义与授权边界不一致。

取舍：采用 `src/magpie_router/` 加 `pyproject.toml` 的可安装布局、`config/` 收策略、`state/{db,snapshots,evidence,work}/` 收运行数据与保留资料；路径集中到唯一模块；拆开混杂的解析、规范、比较、应用职责；移除 v2/v3 兼容与旧单组 `plan set-order`/`apply` 工作流。代价是所有命令、文档、技能和测试引用都要重写，且 `python -m magpie_router` 从「仓库根直接可跑」变为「先安装或设 PYTHONPATH」；`.local/` 里 117 个一次性文件被删除，只保留一份纯文本清单，删除不可从 Git 恢复。收益是领域语义、写入范围、安装契约和数据落位各有唯一来源。

写入范围同步收紧：一次计划对应一份完整规范差异，仅本次已批准并出现在 `route diff` 中的组可以写入；规范外的现存组仍默认跳过。若将来需要单组粒度的变更能力，应重新评估本决定，而不是在代码里保留两套工作流。
